sre-agent por dentro

Um agente de plantão que investiga incidentes em modo só leitura e entrega uma hipótese de causa raiz. Três desenhos mostram o caminho de um incidente, onde cada coisa roda e por quais estados uma investigação passa.

O caminho de um incidente

Só o intake fica ligado o tempo todo, e ele não chama o modelo. A investigação acontece num Job criado para aquele incidente, que lê o cluster com uma identidade sem permissão de escrita.

Dentro do job: onde cada coisa roda

O modelo roda na API da Anthropic e só decide qual tool chamar. As tools executam no container do Job, com as credenciais dele. O modelo nunca vê um token, só o resultado de cada chamada.

Os estados de uma investigação

Todo run termina registrado: SUCCEEDED com o modo de entrega, ou FAILED com um código que diz por quê. O relatório é salvo antes da publicação, então uma falha do Slack não apaga a investigação.

Onde cada parte mora no código

Intake

internal/intake: HMAC, dedupe e o Job criado com client-go.

Job

internal/job: span raiz, ciclo do run, relatório antes da publicação.

Agente

internal/agent: Tool Runner, prompt e a tool submit_rca_report.

Integrações

internal/integrations: Kubernetes, GitHub, histórico e MCP com allowlist.

Estado

internal/store e migrations: Postgres com as regras no próprio banco.

Rastreio

internal/telemetry: OpenTelemetry com destino escolhido por ambiente.
